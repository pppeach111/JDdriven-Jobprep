# 07 学习路径、实践与日程模块开发手册

## 1. 模块目标

将能力图谱中的高优先级、可弥补差距转换为有限时间内可完成、可验收、可复测的学习路径。它不是“让大模型列课程链接”，而是一个受岗位目标、前置依赖、用户时间和证据要求约束的计划系统。

## 2. 输入

- 目标岗位及截止/计划投递日期；
- 岗位要求与重要性；
- 用户能力等级、维度与置信度；
- 差距类型和优先级；
- 用户每周可用时间；
- 不可学习时段；
- 用户偏好的学习形式；
- 已完成课程和项目；
- 资源库、任务库及前置依赖。

## 3. 输出

每个计划包括：

- 总目标和预计周期；
- 本周期优先补齐能力；
- 学习单元；
- 微型实践；
- 具体产物与验收标准；
- 复测节点；
- 每日/每周日程；
- 调整原因；
- 完成后对目标岗位的预计影响。

## 4. 学习任务结构

```text
任务名称：实现热点内容缓存与失效策略
对应差距：Redis实践缺口
对应JD：“熟悉Redis缓存及常见问题”
前置能力：Redis数据结构 L2、Spring Boot L2
学习资料：官方文档2篇、示例仓库1个
实践产物：代码提交、测试、设计说明
验收条件：功能测试通过；解释穿透与击穿；提供对比数据
预计用时：6小时
复测方式：新场景诊断题 + 项目追问
简历转化条件：用户确认结果真实且指标可复现
```

缺少产物或验收条件的内容只能称为“学习建议”，不能作为正式任务进入主计划。

## 5. 学习路径生成

### 5.1 先过滤

不进入学习路径：

- 学历、毕业年份等无法短期改变的资格阻断；
- 与目标岗位相关度低的能力；
- 已有高可信证据证明满足的能力；
- 在剩余时间内明显不可完成的高跨度目标；
- 来源不可信或链接失效的资料。

### 5.2 再排序

```text
task_value =
  差距优先级
  × 对多个目标岗位的复用率
  × 可验收程度
  × 预计提升幅度
  / 预计耗时与风险
```

### 5.3 处理依赖

能力和任务形成有向无环图。例如：

```text
Redis数据结构
   → 缓存基本使用
      → 缓存一致性
         → 高并发缓存设计
            → 压测与监控
```

先进行拓扑排序，再根据时间预算选择任务。发现循环依赖时必须报错并由管理员修正标准库。

## 6. 日程安排

日程不是简单平均分配：

- 高认知负荷任务安排在用户长时间段；
- 15～30分钟可完成阅读或复习；
- 实践任务拆成准备、实现、测试、总结；
- 每周至少一个缓冲时段；
- 复测不能紧贴答案学习，应留出合理间隔；
- 临近岗位截止时优先完成能影响投递决策的任务；
- 用户拖延后重新规划，不把所有任务堆到最后一天。

首版提供周视图和列表视图即可，拖拽和 ICS 导出属于 P1。

## 7. 资源库

### 7.1 来源优先级

1. 官方文档、标准和课程；
2. 维护活跃的开源项目和官方示例；
3. 高质量高校公开课程；
4. 有稳定作者与更新记录的技术文章；
5. 其他社区内容。

### 7.2 资源条目

- 标题、URL、作者/组织；
- 对应技能和等级；
- 内容形式、语言和预计时长；
- 前置能力；
- 最后访问时间和状态码；
- 是否需要登录或付费；
- 许可证或使用限制；
- 人工审核状态。

大模型可以寻找候选资源，但资源进入推荐前必须完成链接有效性检查和来源评级。不要生成未经核验的虚假链接。

## 8. 动态调整

触发重新规划：

- 用户提前或延期完成任务；
- 复测结果高于或低于预期；
- 目标岗位关闭或更换；
- 用户调整每周可用时间；
- 学习资源失效；
- 新岗位显示某项能力更高频；
- 新证据已经证明某项能力。

调整时保留用户已完成任务和手动锁定日程，并说明变更原因。

## 9. 完成、验收与写回

任务状态：

```text
PLANNED → IN_PROGRESS → SUBMITTED → VERIFIED
                           ↓           ↓
                        REVISE      RETEST_DUE
```

用户点击“完成”不等于能力已经提升。只有产物验收或复测通过后，才写入较高权重证据。阅读类任务只能提供低权重学习记录。

## 10. MVP

- 两周滚动计划；
- 每周时间预算；
- 能力依赖排序；
- 资源库与链接核验；
- 学习、实践、复测三类任务；
- 列表与课程表周视图；
- 任务完成后的图谱写回；
- 计划自动调整和原因说明。

## 11. 验收标准

- 资格阻断不会被生成学习任务；
- 所有正式任务都有对应岗位差距；
- 至少 80% 的正式任务有产物和验收标准；
- 所有推荐链接经过有效性检查并显示来源；
- 计划总时长不超过用户时间预算；
- 前置任务顺序正确；
- 复测失败会调整后续计划；
- 用户能看懂“为什么先做这个”。
