# 06 靶向文本面试模块开发手册

## 1. 模块定位

面试模块不是通用聊天机器人，而是能力图谱的证据采集器。它围绕目标 JD、简历陈述和已有薄弱点动态追问，验证：

- 用户是否理解简历中声称使用的技术；
- 用户能否解释自己的决策与贡献；
- 用户能否将知识迁移到新场景；
- 回答中是否暴露新的知识、实践或表达缺口。

首版只做文本面试。语音是后续交互层扩展，不应影响核心逻辑。

## 2. 面试类型

### 2.1 简历项目深挖

从具体简历陈述生成追问链。例如：

```text
简历：使用 Redis 将接口响应时间降低 30%
  → 原始瓶颈如何定位？
  → 为什么选择 Redis 而非本地缓存？
  → 30% 如何测量，指标是平均值还是 P95？
  → 数据更新时如何保证一致性？
  → Redis 不可用时系统如何处理？
```

### 2.2 岗位知识考察

根据岗位要求选择尚未验证或证据较弱的能力，避免对已有高可信证据反复提问。

### 2.3 场景与系统设计

给出与岗位接近但不等同于用户项目的新场景，检查迁移、权衡与边界意识。

### 2.4 行为与协作

围绕简历真实经历提问，如冲突、延期、需求变化和个人贡献。首版采用结构化 STAR 评价，但不做人格测评。

## 3. 会话准备

创建面试前生成 `InterviewBlueprint`：

- 目标岗位和重点要求；
- 要验证的 3～5 项能力；
- 简历中需要核实的 2～3 条陈述；
- 每项能力期望达到的等级；
- 已有证据和不可重复询问内容；
- 预计时长、题量和结束条件；
- 禁止问题，如隐私、歧视性问题。

蓝图由程序约束，大模型不能随意把面试带到无关领域。

## 4. 动态追问策略

每轮回答后先分类：

- `CLEAR_CORRECT`：正确且有细节，可提高难度；
- `PARTIAL`：方向正确但缺关键点，追问缺口；
- `VAGUE`：只有术语，要求举例或说明过程；
- `CONTRADICTORY`：与简历/前文冲突，请用户澄清；
- `INCORRECT`：指出问题后切换到诊断性问题；
- `OFF_TOPIC`：温和拉回问题；
- `INSUFFICIENT_EVIDENCE`：无法判定，换题型验证。

追问应回答“为什么问”：

```text
当前问题考察：缓存一致性
追问依据：用户提出“删除缓存”但未说明并发更新
```

这个解释可以在面试结束后展示，不必在作答时暴露评分点。

## 5. 面试评分

### 5.1 技术题维度

- 技术正确性；
- 回答完整性；
- 场景适用性；
- 边界条件意识；
- 方案权衡；
- 表达结构；
- 与项目证据的一致性。

### 5.2 项目题维度

- 背景和目标是否清楚；
- 个人职责是否明确；
- 技术选择是否有依据；
- 结果是否有测量方法；
- 是否能解释失败和改进；
- 陈述是否与简历一致。

### 5.3 评分约束

- 每项分数必须对应评分量表；
- 每项判断引用回答原句；
- 不因为语言华丽而提高技术正确性；
- 不因为答案简短而直接判错；
- 对存在争议的技术方案允许多种正确答案；
- 低置信度结果不直接大幅调整能力等级。

## 6. 会话状态机

```text
PREPARING
  → ASKING
  → EVALUATING
  → FOLLOW_UP 或 NEXT_TOPIC
  → FINAL_REVIEW
  → COMPLETED
```

结束条件：

- 所有目标能力达到最小证据量；
- 已达到时间或题量上限；
- 连续多轮无法有效作答；
- 用户主动结束；
- 内容安全或服务异常。

中断后可恢复，已完成回答不得丢失。

## 7. 面试报告

报告不只给总分，应包含：

- 本次针对的 JD 和能力；
- 每项能力的表现与证据；
- 回答较好的具体片段；
- 错误、缺失和矛盾点；
- 项目表达问题；
- 对能力图谱的更新；
- 建议学习/实践任务；
- 建议复测项；
- 不确定和需人工确认的结论。

用户可对报告标记“判断不准确”并提供原因，形成后续评估数据。

## 8. 提示词与输出约束

建议拆成三个模型任务，而不是一个超长提示词：

1. 回答分析：按量表生成结构化评价；
2. 追问决策：根据蓝图和评价选择下一动作；
3. 报告生成：将结构化结果转化为用户可读说明。

所有输出使用 JSON Schema。若解析失败，最多自动重试一次；仍失败则保存回答并使用预设问题继续，避免整场面试中断。

## 9. MVP

- 支持 Java 后端岗位；
- 支持 15～20 分钟文本面试；
- 3种模式：项目深挖、岗位知识、混合面试；
- 每轮动态追问；
- 评分依据可追溯；
- 面试证据写回能力图谱；
- 生成结构化报告；
- 支持中断恢复。

## 10. 验收标准

- 至少 80% 的问题可映射到目标 JD 或简历具体内容；
- 动态追问与上一轮回答存在可解释关联；
- 同一回答重复评分的波动在可接受范围；
- 技术错误不因表达流畅被评为高分；
- 面试结束后至少输出一条具体优势和一条可执行改进；
- 报告中每个关键结论可定位到回答；
- 与人工面试评价的一致性达到设定阈值。

## 11. 后续语音扩展

语音版只替换输入输出层：语音识别 → 现有文本面试引擎 → 语音合成。新增指标可包括停顿、语速和口头表达结构，但不得从声音推断性格、情绪疾病或录用概率。
