# 02 系统架构与数据设计手册

## 1. 架构目标

系统需要同时支持网页采集、文档理解、确定性规则、生成式 AI 和可追溯证据。首版优先保证：

- 模块边界清晰，可由四人并行开发；
- 每个 AI 结果保留输入、输出、模型版本和引用来源；
- 评分与硬门槛判断可重复；
- 网络采集失败不会拖垮主业务；
- 支持单机本地开发和华为云部署；
- 不因引入图数据库增加不必要复杂度。

## 2. 推荐总体架构

```text
Vue 3 Web 前端
      ↓ HTTPS
Spring Boot 业务 API
      ├─ 用户/目标/岗位/计划/简历
      ├─ 规则与评分引擎
      ├─ 能力图谱服务
      └─ 任务编排与审计
             ↓ 消息/任务
Python Worker
      ├─ 官方岗位发现与页面解析
      ├─ JD/简历结构化提取
      ├─ 测评开放题辅助评分
      ├─ 动态面试追问
      └─ 学习资源候选生成与核验

基础设施
      ├─ RDS：结构化业务数据
      ├─ Redis：缓存、限流、短任务状态
      ├─ OBS：JD、简历、网页快照、报告
      ├─ MaaS：大模型推理
      ├─ ECS/云容器：服务部署
      └─ CodeArts：需求、代码、流水线和部署记录
```

## 3. 为什么首版不用图数据库

能力图谱的“图”首先是一种业务关系，不要求一定使用 Neo4j。首版关系规模小、查询路径可控，使用 RDS 更容易开发、部署和复现。

建议通过关联表表达：

- 岗位要求某项能力；
- 用户拥有某项能力估计；
- 证据支持或削弱某项能力；
- 题目验证某项能力；
- 学习任务提升某项能力；
- 能力依赖另一项能力。

当需要复杂路径推荐或跨岗位大规模分析时，再评估图数据库。答辩中应强调“业务图谱先行，存储技术服从规模”。

## 4. 核心领域对象

### 4.1 用户与目标

| 对象 | 关键字段 |
|---|---|
| User | id、基本信息、隐私同意、时区 |
| JobGoal | 目标名称、城市、岗位类型、毕业年份、到岗时间、每周可用时间 |
| SourceJD | 原始文件/文本、来源、解析版本、快照地址 |
| ResumeVersion | 原文件、结构化内容、用户确认状态、版本号 |

### 4.2 岗位与能力

| 对象 | 关键字段 |
|---|---|
| JobPosting | 企业、职位、地点、官网 URL、开放状态、最后核验时间 |
| JobRequirement | 类型、原文、标准化值、必要性、权重、置信度 |
| Skill | 标准名称、别名、领域、描述、等级标准 |
| SkillDependency | 前置技能、后继技能、依赖强度 |
| JobSkillRequirement | 岗位、技能、要求等级、必要性、来源引用 |

### 4.3 能力证据与测评

| 对象 | 关键字段 |
|---|---|
| UserSkillEstimate | 用户、技能、估计等级、置信度、更新时间 |
| Evidence | 类型、来源、内容摘要、可信度、时间、文件/引用 |
| EvidenceSkillLink | 证据、技能、支持方向、强度 |
| Question | 能力点、题型、难度、评分规则、版本 |
| AssessmentAttempt | 用户、目标、开始/结束时间、能力前后状态 |
| Answer | 题目、回答、客观分、量表分、引用和人工复核状态 |

### 4.4 学习、面试与简历

| 对象 | 关键字段 |
|---|---|
| InterviewSession | 目标岗位、轮次、策略、报告 |
| InterviewTurn | 问题、回答、追问依据、评分项 |
| LearningResource | URL、来源类型、关联技能、最后核验时间 |
| LearningTask | 技能、产物、验收标准、预计时长、状态 |
| ScheduleItem | 开始/结束、依赖任务、用户调整记录 |
| ResumeSuggestion | 原文、建议文本、证据引用、用户确认状态 |

## 5. 统一等级与置信度

### 5.1 技能等级

所有模块统一使用六级能力定义：

| 等级 | 定义 |
|---:|---|
| L0 | 未接触或无有效信息 |
| L1 | 知道基本术语和用途 |
| L2 | 能在指导下完成常见任务 |
| L3 | 能独立应用并处理常见问题 |
| L4 | 能解释原理、诊断异常并权衡方案 |
| L5 | 能设计复杂方案、指导他人并沉淀方法 |

每项技能还需要具体锚点。例如 Redis L3 的标准不能直接套用到沟通能力。

### 5.2 置信度

置信度表示“系统对当前等级判断有多确定”，不是能力水平本身。建议范围 0～1，考虑：

- 证据类型可靠度；
- 多种题型的一致性；
- 证据新鲜度；
- 是否有相互矛盾的结果；
- 是否经过实践任务；
- 是否经过用户或人工确认。

前端必须同时展示等级与置信度，例如“L3，置信度 78%”，不能只展示单一分数。

## 6. AI 与确定性程序的边界

### 6.1 适合使用大模型

- JD、简历、网页正文的候选结构化提取；
- 技能别名和上下文归一化；
- 开放题按明确量表逐项辅助评分；
- 根据回答选择追问角度；
- 生成学习任务说明和简历表达候选；
- 对复杂判断生成面向用户的解释。

### 6.2 必须由程序控制

- 学历、毕业年份、城市等硬门槛判断；
- 匹配分、差距优先级和置信度更新；
- 题目曝光、难度升降和结束条件；
- 学习任务依赖、时间安排和状态流转；
- URL 去重、开放状态和最后核验时间；
- 权限、隐私、审计日志和数据删除；
- 模型输出 Schema 校验与重试。

## 7. 服务接口建议

首版统一使用 `/api/v1` 前缀，以下 API 仅为最小接口集。请求和响应必须遵守 [14-contracts-and-schemas.md](./14-contracts-and-schemas.md)；未列出的字段不得由实现自行发明。

```text
POST /api/v1/goals                         创建求职目标
POST /api/v1/goals/{id}/jd                 导入目标 JD
POST /api/v1/resumes                       导入简历
POST /api/v1/goals/{id}/analyze            触发联合解析
GET  /api/v1/goals/{id}/capability-map     获取能力、证据与差距

POST /api/v1/goals/{id}/jobs/discover      发起官方岗位发现（异步）
GET  /api/v1/goals/{id}/jobs               获取已核验候选岗位
POST /api/v1/jobs/{id}/verify              重新核验开放状态（异步）

POST /api/v1/assessments                   创建自适应测试
POST /api/v1/assessments/{id}/answers      提交回答并返回下一题
GET  /api/v1/assessments/{id}/result       获取结果和能力更新

POST /api/v1/interviews                    创建靶向面试
POST /api/v1/interviews/{id}/turns         提交回答并获取追问
GET  /api/v1/interviews/{id}/report        获取报告

POST /api/v1/goals/{id}/learning-plan      生成学习计划（异步）
PATCH /api/v1/learning-tasks/{id}          更新任务或提交证据
POST /api/v1/learning-tasks/{id}/verify    验收并触发复测（异步）

POST /api/v1/resumes/{id}/target           创建岗位靶向版本
GET  /api/v1/resumes/{id}/suggestions      获取证据化建议
```

### 接口行为约定

- 导入和生成类接口返回资源 ID、任务 ID 或结构化结果，不返回无法验证的“成功”；
- 异步接口使用任务状态轮询，不要求前端保持长连接；
- `POST` 任务必须支持幂等键，重复提交不重复抓取、计分或写入证据；
- `PATCH` 必须检查版本或 `updatedAt`，冲突返回 `CONFLICT`；
- 所有用户资源按当前用户隔离，越权访问返回统一 `NOT_FOUND`，避免泄露资源存在性；
- 所有接口失败返回契约文件规定的外层错误结构和 `traceId`。

## 8. 异步任务

以下操作进入异步队列：

- 批量搜索和抓取官方岗位；
- PDF/DOCX/OCR 解析；
- 网页快照与正文抽取；
- 大批量资源链接健康检查；
- 面试报告和学习计划生成；
- 岗位开放状态定期复核。

任务状态统一为 `PENDING/RUNNING/SUCCEEDED/PARTIAL/FAILED/CANCELLED`，每个失败任务保留错误类型和重试次数。前端不得无限转圈，应显示阶段进度和可恢复操作。

## 9. 可观测与复现

每次模型调用记录：

- 调用场景与业务 ID；
- 提示词模板版本；
- 模型与参数；
- 输入内容哈希；
- 原始输出和解析结果；
- Schema 验证错误；
- 用时和费用；
- 用户最终是否接受。

涉及个人简历时，日志默认脱敏，不在普通应用日志记录姓名、电话、邮箱和原始简历正文。
