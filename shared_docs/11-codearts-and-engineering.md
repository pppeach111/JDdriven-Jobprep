# 11 CodeArts、Git 与工程协作手册

## 1. 基本要求

项目必须在全新仓库从零开发，保留真实、连续、可审查的 Git 历史。可以复用成员已经掌握的技术经验，但不得复制 MindSpace 的代码、历史、素材或伪造提交过程。

CodeArts 不应只在最后导入代码，而要覆盖：需求分析、任务拆分、代码辅助、代码评审、调试测试、流水线、云上部署、缺陷与版本管理。

## 2. 仓库建议

首版建议单仓库，降低跨仓依赖：

```text
career-path/
├─ frontend/
├─ backend/
├─ worker/
├─ database/
├─ datasets/
├─ evaluation/
├─ deploy/
├─ docs/
└─ README.md
```

Python AI Worker 负责采集与 AI 服务，不要为了展示“微服务”过度拆分。

### 2.1 第三方依赖准入

每个新增依赖必须在工作项中记录用途、固定版本、许可证、维护状态、替代方案以及对镜像体积和部署成本的影响。大型平台或会改变核心架构的依赖需要单独评审，不得仅因示例项目使用就引入。

GitHub 示例项目只能用于理解思路，禁止复制其业务代码、目录结构、提示词、数据集或提交历史；依赖应作为边界清晰的库使用，不能让第三方项目成为本项目的核心业务骨架。新增依赖必须通过构建、许可证/安全扫描和最小集成测试。

## 3. 分支与提交

建议分支：

- `main`：可部署、可演示；
- `develop`：集成分支；
- `feature/<issue-id>-<short-name>`：功能；
- `fix/<issue-id>-<short-name>`：修复；
- `release/<version>`：提交前冻结版本。

提交要求：

- 一次提交完成一个可解释改动；
- 提交信息关联 CodeArts 工作项；
- 不使用“update”“fix bug”等无意义描述；
- 不提交密钥、真实简历、缓存和大模型原始隐私数据；
- 不为“看起来开发很久”拆分或补写虚假提交；
- AI 生成代码必须由成员理解、测试和评审。

提交示例：

```text
feat(graph): calculate evidence confidence caps #42
fix(crawler): classify disabled ATS apply buttons #57
test(assessment): add rubric consistency fixtures #63
docs(eval): define job-status annotation guide #71
```

## 4. CodeArts 工作项

层级建议：

```text
Epic：能力评估闭环
  Feature：自适应测评
    Story：用户完成 Redis 快速测试
      Task：实现选题状态机
      Task：编写 Redis L2/L3 题目
      Task：接入能力证据写回
      Test：难度升降与结束条件
```

每个 Story 至少包含用户价值、验收标准、依赖、负责人、第二责任人、预计工时、关联接口和实际结果。

## 5. 接口优先协作

模块并行开发前冻结：

- OpenAPI 接口；
- JSON Schema；
- 状态枚举；
- 错误码；
- 示例输入输出；
- 版本和兼容策略。

前端使用接口 Mock 时必须明确标识，集成验收只能使用真实后端和真实任务状态。

## 6. 代码评审

所有 P0 代码至少一人评审。检查：

- 是否满足工作项验收；
- 是否改变数据契约；
- 模型输出是否有 Schema 和失败处理；
- 是否记录来源、版本和置信度；
- 是否泄露简历或密钥；
- 是否有超时、重试和限流；
- 是否包含测试；
- 是否引入不必要复杂度。

关键评分、硬门槛和证据聚合规则必须两人评审。

## 7. 测试层级

- 单元测试：规则、评分、状态机、解析器；
- 契约测试：Java API 与 Python Worker；
- 集成测试：数据库、对象存储、模型 Mock 或沙箱；
- 端到端测试：JD 导入到复测闭环；
- 数据回归：固定岗位、题目和回答集；
- 部署烟测：云环境关键路径。

模型结果还要执行 JSON Schema、禁止字段、来源、固定评测集和少量人工抽查。

## 8. 流水线

```text
依赖安装
  → 格式与静态检查
  → 单元测试
  → 构建镜像/产物
  → 安全与密钥扫描
  → 数据库迁移验证
  → 部署测试环境
  → 冒烟测试
  → 人工批准后部署演示环境
```

任何阶段失败不得自动覆盖稳定演示环境。

## 9. 配置与密钥

- 密钥只进入 CodeArts、云端密钥管理或环境变量；
- 提供 `.env.example`，不提供真实值；
- 本地、测试、演示环境分离；
- 模型、搜索、对象存储、数据库均可替换配置；
- 记录云资源和第三方服务版本；
- 演示账号使用虚构或明确授权数据。

## 10. 留痕材料

从第一周开始每周归档：

- CodeArts 工作项截图或导出；
- 关键提交与评审；
- 编程助手参与需求、生成、调试和部署的实例；
- 流水线运行；
- 版本演示视频；
- 指标变化；
- 失败案例和改进记录。

最后再补留痕容易缺少关键过程，也无法证明真实开发轨迹。

## 11. 发布定义

每个周版本应具备版本号、变更日志、可部署产物、迁移脚本、示例账号、演示数据、已知问题、回滚方式和测试报告。
