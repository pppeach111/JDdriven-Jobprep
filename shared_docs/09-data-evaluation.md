# 09 数据集与评测计划书

## 1. 评测目标

评测需要回答四个问题：

1. 系统是否找到了真实、官方、仍可申请的岗位？
2. 系统是否正确理解 JD、简历、能力和硬门槛？
3. 测评与面试能否较稳定地估计能力并发现差距？
4. 学习闭环是否帮助用户提高并产生更可靠证据？

只展示几个成功案例不足以证明系统有效，需要离线数据集、人工基准、小规模用户实验和消融实验。

## 2. 数据集分层

### 2.1 官方岗位数据集

目标规模：

- 20～30 家企业官方招聘站；
- 300～500 条岗位页面；
- 其中至少 100 条 Java 后端或相近岗位；
- 包含开放、关闭、删除、通用人才库、重复岗位；
- 同时包含静态和动态页面。

人工标注：是否官方、企业、标题、地点、招聘类型、学历、毕业年份、专业、到岗要求、技能、开放状态、重复岗位组和原文位置。

### 2.2 JD—能力标注集

目标规模为 80～120 份 Java 后端 JD。至少两名成员独立标注标准技能、要求等级、核心/优先/加分、明示/隐含、硬门槛和原文证据；分歧由第三人裁决，并持续维护标注准则。

### 2.3 简历—证据数据集

目标规模为 30～50 份经过脱敏和授权的学生简历，或团队自行构造且明确标识的合成简历。

标注内容包括：经历与技能关联、证据类型、缺失事实、夸大或冲突风险、需要进一步测试的能力。不得私自收集或公开同学的真实简历。

### 2.4 题库和回答集

- 140～180 道首版题目；
- 每道题至少经过一名技术成员复核；
- 收集 20～40 名学生的匿名作答；
- 邀请 3～5 名有 Java 开发经验的高年级学生或工程师提供参考评价；
- 开放题由两人独立评分，用于检验模型评分一致性。

## 3. 离线指标

### 3.1 岗位发现

| 指标 | 说明 | 建议目标 |
|---|---|---:|
| 官方来源准确率 | 返回结果是否为官方申请渠道 | 100% |
| Precision@5 | 前5个岗位与目标是否相关 | ≥0.80 |
| 岗位去重准确率 | 合并和保留是否正确 | ≥0.90 |
| 开放状态准确率 | OPEN/CLOSED 判断 | ≥0.85 |
| 核心字段抽取 F1 | 标题、地点、年份、技能等 | ≥0.85 |
| 硬门槛准确率 | 满足/不满足/未知 | ≥0.90 |

### 3.2 JD 与简历理解

- 技能提取 Precision、Recall、F1；
- 技能标准化准确率；
- 必要性分类准确率；
- 原文引用正确率；
- 无来源新增字段率，目标接近 0；
- 简历事实结构化准确率；
- 用户纠错率。

### 3.3 测评和面试

- 客观题评分准确率；
- 开放题模型评分与人工评分的相关性；
- 相邻能力等级区分度；
- 同一回答重复评分稳定性；
- 自适应结束规则正确率；
- 能力结论证据覆盖率；
- 动态追问相关性人工评分；
- 用户完成率和平均耗时。

### 3.4 学习与简历

- 计划时间是否超出用户预算；
- 任务前置依赖正确率；
- 正式任务可验收覆盖率；
- 资源链接有效率；
- 复测成绩或能力估计变化；
- 简历建议证据引用率；
- 无依据新增事实数，必须为 0；
- 建议接受率与人工质量评分。

## 4. 用户实验

招募 20～30 名准备实习或校招的学生，至少完成：

1. 上传一份目标 JD 和脱敏简历；
2. 查看官方岗位结果；
3. 完成一次 10 分钟测评；
4. 查看能力差距和两周计划；
5. 对准确性、可理解性和有用性评分。

如果时间允许，选择 8～12 人进行一周短期学习与复测，但不把一周实验解释为长期就业效果。

主观量表采用 1～5 分评价岗位相关性、门槛解释、能力判断、测试针对性、计划可执行性、继续使用意愿和节省时间。同时保留所有负面反馈。

## 5. 消融实验

### 5.1 关键词匹配 vs 证据图谱

- 基线：简历与 JD 的关键词或向量相似度；
- 完整方案：硬门槛 + 标准技能 + 证据置信度；
- 比较岗位排序、错误推荐和解释质量。

### 5.2 固定题库 vs 自适应测评

比较达到相近判断稳定度所需的题量、时间、完成率和能力边界识别效果。

### 5.3 一次生成计划 vs 复测反馈计划

比较复测失败后能否正确调整任务，证明动态图谱相对一次性报告的价值。

### 5.4 无来源生成 vs 来源核验

比较学习资源失效或虚假链接率，以及岗位开放状态误判率。

## 6. 数据切分与防泄漏

- 提示词调优集、验证集、最终测试集分离；
- 同一企业的高度相似岗位尽量放在同一分组；
- 最终测试集在方案稳定后冻结；
- 不使用测试集持续修改提示词；
- 报告模型、提示词、规则和数据版本；
- 人工评审尽量不知道结果来自哪种方案。

## 7. 错误分析

建立错误样例库，包括：

- 官方 ATS 域名误判；
- 岗位已关闭但仍返回；
- 学历或年份条件漏提取；
- 技能别名归一化错误；
- 模型评分被流畅表达误导；
- 学习资源链接失效；
- 简历建议夸大事实；
- 证据重复计权；
- 复测后能力异常跃迁。

每周评审最高频的五类错误，优先修复根因而非只修演示样例。

## 8. 最终评测报告

报告必须包含：

- 数据来源、规模、授权和脱敏方式；
- 标注准则及一致性；
- 基线、完整方案和消融结果；
- 平均值之外的失败案例；
- 样本量及置信区间或波动范围；
- 系统限制和不可外推结论；
- 可复现实验步骤。
