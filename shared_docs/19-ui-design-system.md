# 19 前端体验与视觉系统

## 1. 适用范围与设计方向

本文是所有前端页面、组件、图表、交互状态和视觉评审的单一设计依据。适用于 CP-010，也适用于其他任务新增或修改的用户界面。

设计判断：

> 面向准备实习和校招的学生，构建一个专业、克制、证据优先的求职决策工作台。界面应让用户先看懂“结论、依据、下一步”，而不是营造普通招聘门户、游戏化学习产品或大模型聊天壳的观感。

首版设计参数：

- 视觉变化度：4/10，以稳定一致为先，采用 Beautiful UI 的 compact、细边界和任务状态语言；
- 动效强度：2/10，仅用于反馈和状态变化；
- 信息密度：7/10，桌面端充分利用空间，移动端主动降维；
- 主题：首版只要求高质量浅色主题，不为展示效果强行增加深色主题；
- 风格：冷灰中性底色、单一靛蓝紫强调色、hairline 边界、紧凑控件、轻量层叠阴影和明确状态行；不使用装饰性渐变；
- 核心感受：可信、清楚、可行动，而不是“炫技”或“AI 感”。

> **2026-09-21 修订**：视觉方向改为参照 [Beautiful UI](https://www.beautifului.dev/) 的组件信息结构，
> 在 Vue 3 中采用本地适配，而不是把 React/Tailwind registry 直接引入运行时。核心原则是中性画布、细边界、紧凑控制、任务行、上下文卡和可核验状态。
> 原先的大面积玻璃拟态和装饰性渐变不再作为默认组件表面；仅保留单一靛蓝紫品牌色与业务状态色。
> 变更理由、影响页面与令牌迁移方式见 `18-current-state-and-next-actions.md` 的 CP-010 记录，本文件末尾 §18 为修订台账。

## 2. 设计原则

### 2.1 结论必须带证据

- 匹配、差距、能力等级、置信度、开放状态和简历建议都必须提供来源入口；
- 来源入口使用统一的“查看依据”动作，打开抽屉或详情区，不在页面间随意跳转；
- 等级与置信度是两个概念，必须并列展示，不能合并成一个含糊分数；
- `UNKNOWN`、待确认和证据不足必须可见，不用中性色伪装成“满足”。

### 2.2 下一步优先于信息堆积

- 每个主要页面只保留一个主操作；
- 页面首屏优先回答“当前状态是什么”和“下一步做什么”；
- 次要解释进入展开区、来源抽屉或详情面板；
- 不用多个同权重大卡片争夺注意力。

### 2.3 统一结构优先于局部创意

- 复用相同的页面标题、筛选、状态、来源和错误恢复模式；
- 先使用设计令牌和共享组件，再写局部样式；
- 不因某一页面截图好看而引入新的颜色、圆角、阴影或排版体系；
- 产品名尚未最终确定：界面展示使用当前工作名“职径”，令牌名和组件名一律使用语义名（如 `--color-primary`、`--shadow-card`），不依赖 `careerpath` 品牌字符串；
- 工作名变更时只替换展示层文案与品牌标记，不得让令牌名、组件名和路由随之改名。

### 2.4 状态必须诚实

- 异步任务显示真实阶段、已完成内容和可恢复动作，不使用无限转圈；
- Mock、演示预置、模型推断、用户确认和系统事实必须有不同标记；
- 失败页面保留已经成功的数据，不把局部失败渲染成整页空白；
- 时间敏感信息显示最后核验时间和是否过期。

## 3. 信息架构与应用外壳

### 3.1 一级导航

首版一级导航固定为：

1. 求职目标；
2. 能力与证据；
3. 岗位发现；
4. 测评与面试；
5. 学习计划；
6. 简历建议。

设置、数据授权、帮助和退出放入用户菜单，不与主闭环争夺一级导航位置。不要为每个后端实体创建一个导航入口。

### 3.2 桌面外壳

- 全宽段：顶部横向导航（`height: 70px`，`position: sticky`）+ 弹性主内容区；
- 顶部导航结构固定为：品牌标记 → 一级导航（6 项，横向 pill）→ 搜索 → 通知 → 用户；
- `1024～1359px`：顶部导航隐藏部分导航文案只留图标，搜索框收窄，横向留白由 32px 收至 22px；
- `<1024px`：顶部导航收起一级导航链接（导航入口移入抽屉），保留品牌、搜索与用户操作；
- 主内容最大宽度按任务选择：表单 720px、阅读/测评 800px、数据工作台 1440px；
- 页面标题区包含返回关系、标题、简短说明、状态和唯一主操作；
- 全局目标切换器置于导航顶部或页面标题区，不能散落在每个模块内。

### 3.3 移动外壳

- `<768px` 沿用顶部横向导航（高 62px），一级导航链接收起进抽屉，不把桌面导航压窄后继续显示；
- 页面转为单列，次要详情进入抽屉或折叠区；
- 仅当页面存在单一关键提交动作时使用底部固定操作区；
- 数据表优先转为摘要列表或主从详情，不默认依赖横向滚动；
- 移动端目标是完成关键流程和查看结果，不要求承载全部桌面分析密度。

## 4. 设计令牌

实现时使用 CSS 自定义属性或等价的 Vue 主题变量。禁止在组件中散落近似颜色和任意间距。

### 4.1 颜色

令牌分三层，组件只能引用第 2、3 层，不得直接引用原始色值：

1. **Layer 1 原始值**：`--indigo-600`、`--slate-900`、`--teal-600` 等，仅在本令牌文件内出现；
2. **Layer 2 语义**：下表，业务组件唯一允许引用的颜色层；
3. **Layer 3 组件**：`--shadow-*`、`--radius-*`，见 §4.3。

| 语义令牌 | 建议值 | 用途 |
|---|---:|---|
| `--color-canvas` | `#F8F7FC` | 应用背景 |
| `--color-canvas-tint-a` | `#E7EAFB` | 背景左上角淡靛蓝径向光晕 |
| `--color-canvas-tint-b` | `#F3E8FB` | 背景右上角淡紫径向光晕 |
| `--color-surface` | `#FFFFFF` | 主表面、表单、抽屉 |
| `--color-surface-subtle` | `#F1F0F8` | 次级分组、悬停背景 |
| `--color-surface-glass` | `rgba(255,255,255,.72)` | 玻璃卡片底色 |
| `--color-surface-glass-strong` | `rgba(255,255,255,.90)` | 玻璃卡片内的不透明子块（事实格、差距行） |
| `--color-surface-sunken` | `rgba(255,255,255,.62)` | 说明区、次要面板 |
| `--color-text` | `#16172B` | 主要文本 |
| `--color-text-muted` | `#6A6E8C` | 辅助说明 |
| `--color-text-subtle` | `#9A9EBA` | 三级文本、占位符、时间戳 |
| `--color-border` | `#E1E3EA` | 默认边框和分隔线 |
| `--color-border-strong` | `rgba(22,23,43,.18)` | 强调分隔、输入边界 |

| `--color-primary` | `#5B4BE8` | 主按钮、选中态、关键链接 |

| `--color-primary-soft` | `#EEF0FF` | 选中背景、轻提示 |

| `--color-success` | `#0F8F80` | 已验证、已完成 |
| `--color-success-bg` | `#E4F5F2` | 成功态标记底色 |
| `--color-warning` | `#B87808` | 待确认、即将过期 |
| `--color-warning-bg` | `#FCF3E2` | 警告态标记底色 |
| `--color-danger` | `#C9353B` | 错误、不满足、破坏性操作 |
| `--color-danger-bg` | `#FDECEC` | 危险态标记底色 |
| `--color-info` | `#2F66D6` | 中性流程信息 |
| `--color-info-bg` | `#EAF0FD` | 信息态标记底色 |
| `--color-conflict` | `#C8498A` | 证据冲突（语义上区别于“错误”） |
| `--color-conflict-bg` | `#FBEBF3` | 冲突态标记底色 |
| `--color-neutral` | `#6A6E8C` | `UNKNOWN`、未开始、无信号的中性状态 |
| `--color-neutral-bg` | `rgba(22,23,43,.05)` | 中性状态标记底色 |
| `--color-scrim` | `rgba(22,23,43,.38)` | 抽屉 / 模态框背后的场景压暗遮罩，不承载语义 |
| `--color-focus` | `#1E78C5` | 键盘焦点环，配合 `outline-offset: 2px` |

规则：

- 主色只表达操作、选中和产品主线，不用作大面积装饰背景；
- 成功、警告、危险、冲突不能只靠颜色表达，必须同时配图标和文本；带底色的状态标记必须成对使用 `--color-*-bg` 与 `--color-*`；
- 状态标记的底色**不得**提高正文与背景的对比度要求：玻璃层上的状态文本仍需满足 §11 的 WCAG AA；
- 渐变只允许出现在四处：主按钮、选中导航项、**品牌标记**（品牌方块，尺寸 ≤ 40×40px）、数据图形（条形/环形）。禁止用于页面背景、装饰色块、“AI 感”光带和文字；
- 玻璃拟态允许使用，但受 §4.5 约束；禁止荧光光晕（高饱和外发光）和高饱和彩色阴影，边界见 §4.3；
- 不为不同模块各自分配品牌色。

### 4.2 字体与字号

字体栈：

```css
font-family: "Plus Jakarta Sans", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, -apple-system, sans-serif;
```

字体引入方式：

- **自托管**，通过 `@font-face` 引入，仅包含 `400 / 600 / 700 / 800` 四个字重，`font-display: swap`；
- **不引 Google Fonts CDN**：中国大陆网络下不可达，会造成首屏阻塞并影响 LCP 目标；
- 中文字形回落到系统字体（PingFang SC / 微软雅黑 / Noto Sans CJK SC），不为中文引入额外 Web 字体；
- 若字体文件尚未就绪，先使用中文系统字体，不因字体引入阻塞首版。

| 角色 | 字号/行高 | 字重 |
|---|---|---|
| 页面标题 | 30/38px | 800 |
| 区块标题 | 22/30px | 700 |
| 组件标题 | 18/26px | 700 |
| 正文 | 14/22px | 400 |
| 强调正文 | 14/22px | 700 |
| 辅助文本 | 12/18px | 500 |
| 数据数字 | 24/30px 或 32/38px | 700～800 |

中文正文不使用过密字距；英文 ID、时间和数值可使用等宽数字特性。标题尽量在两行内完成，不通过超大字号制造空洞首屏。

### 4.3 间距、圆角和阴影

- 基础间距：4px；常用序列：4、8、12、16、24、32、48、64；
- 页面左右留白：桌面 32px，平板 24px，移动 16px；
- 网格：桌面 12 列/24px 间隙，平板 8 列/16px，移动 4 列/12px；
- 圆角令牌：
  - `--radius-control`：8px（输入框、事实格、差距行、日期格）；
  - `--radius-icon`：8px（图标容器）；
  - `--radius-card`：14px（卡片）；
  - `--radius-panel`：18px（行动条、大面板）；
  - 状态标记使用 6px 紧凑圆角；按钮、输入框和搜索框使用 `--radius-control`，仅需要强调连续性的筛选器才使用 `--radius-pill: 999px`；
- 阴影令牌（Layer 3，只允许引用令牌，不写内联阴影）：

  | 令牌 | 值 | 用途 |
  |---|---|---|
  | `--shadow-card` | `0 4px 24px rgba(0,0,0,.04), 0 1px 3px rgba(22,23,43,.03)` | 卡片常态 |
  | `--shadow-card-hover` | `0 12px 34px rgba(70,60,180,.12), 0 2px 6px rgba(22,23,43,.05)` | 卡片悬浮 |
  | `--shadow-brand` | `0 8px 22px rgba(91,75,232,.30)` | 品牌按钮、选中导航项 |
  | `--shadow-nav` | `0 6px 24px rgba(70,60,180,.05)` | 顶部导航 |
  | `--shadow-float` | `0 14px 40px rgba(70,60,180,.16)` | 抽屉、下拉、模态框 |

- 阴影使用边界（可核查，替代原“阴影只用于浮层”的绝对禁令）：
  - 卡片常态阴影 alpha ≤ `.05`；悬浮态 ≤ `.14`；品牌投影 ≤ `.32` 且最多 1 层、模糊半径 ≤ 24px；
  - 禁止叠加两层以上彩色阴影，禁止模糊半径 > 32px 的彩色投影，禁止使用非品牌色相的高饱和彩色阴影；
- 同一屏幕避免连续嵌套三层带边框卡片；
- 数据工作台允许卡片网格化，但每个卡片必须承载能独立操作、点击或重复出现的内容，不为分段而分段（呼应 §5.2 与第 168 行的“仪表盘模板感”约束）。

### 4.4 控件尺寸

- 默认输入框和按钮高度 40px；关键表单可用 44px；
- 图标按钮可视尺寸不小于 36px，点击区域不小于 44×44px；
- 标签和状态标记高度 24～28px，不用于承载长句；
- 表格默认行高 48～50px，信息较多时允许 56px，不用固定高度裁切内容。

### 4.5 表面与 Beautiful UI 适配规范

Beautiful UI 的 React registry 仅作为结构和交互参考，本项目不把它作为运行时依赖。Vue 组件默认使用不透明表面和细边界；如未来页面确需透明层，必须满足以下约束，任一不满足即退回不透明底色：

- **嵌套**：禁止“透明层嵌套透明层”。卡片内的子块（事实格、差距行、表格、日期格）使用 `--color-surface-glass-strong`、`--color-surface-subtle` 或纯色底，同一卡片内不得出现第二层 `backdrop-filter`；同级并列的卡片不受限制；
- **参数**：`backdrop-filter: blur(18px) saturate(170%)`；玻璃底色 alpha 取 `.62～.90`；描边使用 `--color-border-glass`；
- **性能**：不做大面积模糊（长列表、横向滚动容器内改为不透明底）；`will-change` 只在**需要随滚动重绘的固定层**（如 sticky 顶部导航、抽屉）声明，不为每张卡片逐个声明——合成层过多反而增加显存与绘制开销；
- **对比度**：玻璃层上的文本必须按**最不利的底层色**核算，正文与交互文本达 WCAG AA（4.5:1）。背景光晕（`--color-canvas-tint-*`）与玻璃叠加后的实际底色若使对比度不达标，改为不透明底；
- **降级**：用 `@supports not (backdrop-filter: blur(1px))` 回落到 `--color-surface` 纯色，层级与可读性不受影响；
- **加载态**：整页加载不得对页面使用模糊或低透明度遮罩（延续 §12）。

### 4.6 Beautiful UI 组件接入规则

- **默认优先级**：任何前端页面设计、组件实现或布局调整，都必须先检查 `frontend/src/components/Beautiful*.vue`。决策顺序固定为“直接复用 → 组合复用 → 扩展共享组件 → 新增共享适配”；只要已有组件能够表达业务语义，就不得在页面内建立平行实现；
- 接入流程固定为：阅读 registry 示例 → 提取信息结构和状态语义 → 编写 Vue 3 本地适配 → 接入现有 API/路由 → 在四档视口验收；
- 组件风格优先选择 Beautiful UI 的 `Loading State`、`Context Cards`、`Task Rows`、`Recommendation Card`、`Filter Table` 和 `Records Table` 语言；本项目已落地为 `BeautifulLoadingState`、`BeautifulContextCard`、`BeautifulTaskRow`、`BeautifulStatus`、`BeautifulButton`、`BeautifulPageHeader` 和 `BeautifulEmptyState`；
- `Chat`、`Prompt Bar`、`Sidebar Nav` 不作为核心产品壳，避免把证据工作台误导成聊天应用；
- registry 的 React/TSX 代码不可直接复制到 Vue 模板，必须保留业务语义、键盘可用性、API 字段和 `UNKNOWN` 状态；
- 适配组件只承载视觉与状态表达，不能生成未由接口返回的进度、等级、置信度或推荐结论。
- 每次前端交付必须列出复用或新增的 `Beautiful*.vue` 组件；未复用现有组件时，必须记录无法覆盖的业务语义和新增共享适配的理由。
- 产品名标记由 `BrandMark.vue` 的自绘几何路径承载（logo 不属图标库范畴，不因此新增 Lucide 图标）；一级页面的标题区、区块、列表、空状态与能力矩阵外壳统一由 `theme.css` 的「页面骨架」段落承载，页面不得自建平行的圆角、字号或阴影刻度。

## 5. 布局模式

### 5.1 页面标题区

结构固定为：上下文/返回关系 → 标题与一句说明 → 状态元信息 → 右侧主操作。移动端主操作下移到标题后或底部操作区。

不在标题区放超过两个按钮；第二个动作使用次要按钮或更多菜单。

### 5.2 分组方式

按以下优先顺序分组：

1. 标题、说明与留白；
2. 浅色背景区；
3. 分隔线；
4. 独立卡片；
5. 阴影浮层。

只有内容确实能独立移动、点击或重复出现时才使用卡片。避免“每一段文字都放进一张白卡”的仪表盘模板感。

### 5.3 主从布局

- 岗位、能力和证据等列表在宽屏使用 5:7 或 4:8 主从布局；
- 详情面板保留明确关闭和返回列表动作；
- 选择列表项不触发整页跳转，URL 应保留可分享的选中项标识；
- 移动端拆分为列表页和详情页，不强行保留双栏。

### 5.4 表单布局

- 一个字段一个清楚标签，说明和错误紧邻字段；
- 相关短字段可双列，长文本、文件上传和关键约束保持单列；
- 多步骤流程显示当前步骤、总步骤和可返回性；
- 表单提交失败保留用户输入，并把焦点移动到错误摘要；
- 不使用仅靠 placeholder 的标签，也不一次展示全部可选高级字段。

## 6. 核心组件模式

### 6.1 能力等级与置信度

统一展示格式：

```text
Redis 缓存设计       L3 独立应用
置信度 78%           4 条证据 · 最近更新 09-16
```

- 等级是主信息，置信度是辅助信息；
- 置信度可使用细进度条，但必须保留数字和文本；
- 不用圆形仪表盘、速度表或单一“综合能力分”替代；
- 变化展示“L2 → L3”和变化原因，不只显示上升箭头。

### 6.2 来源与证据

证据行至少包含：来源类型、摘要、支持/削弱方向、可信度、时间和“查看原文”。

- 原文在右侧抽屉展示并高亮对应片段；
- 简历自述、测试回答、实践产物和人工确认使用明确文本区分；
- 不用颜色区分证据类型作为唯一手段；
- 证据冲突时并列呈现，不静默选择对系统有利的一条。

### 6.3 岗位结果

列表摘要优先展示：岗位、企业、地点、招聘类型、开放状态、匹配原因、关键门槛、最后核验时间。

- “现在适合投”“补齐后再投”“冲刺”“硬门槛不符”“状态待确认”是分组或筛选，不是五种花哨卡片皮肤；
- 申请入口只有在来源官方且 URL 已通过校验时出现；
- 匹配度旁必须可查看构成，不能只给百分比；
- 状态过期时优先提示重新核验，不继续使用绿色成功态。

### 6.4 异步任务进度

显示阶段而不是假百分比：

```text
发现候选 → 抓取页面 → 提取字段 → 核验状态 → 计算匹配
```

- 当前阶段、已完成阶段、失败阶段和可重试动作清楚区分；
- `PARTIAL` 展示已获得结果和未完成原因；
- 预计时间只有基于历史数据时才显示；
- 用户离开页面后任务继续运行，返回时可恢复状态。

### 6.5 按钮和状态标记

- 主按钮：每个视图一个，使用主色实心；
- 次按钮：描边或浅背景；
- 文本按钮：查看来源、展开详情、取消等低风险动作；
- 危险按钮：仅用于删除或撤销，不能与主色混用；
- 按钮文案使用“动词 + 对象”，例如“开始测评”“重新核验岗位”，避免“确定”“下一步”脱离上下文。

## 7. 关键页面模板

### 7.1 求职目标与导入

- 使用 720px 单列步骤表单；
- 步骤建议为“目标 JD → 简历 → 求职约束 → 确认”；
- 上传后展示文件名、解析状态、替换和删除操作；
- 解析结果先让用户确认关键事实，再进入分析；
- 首屏不展示能力图谱、岗位卡片等尚未生成的假数据。

### 7.2 分析概览

首屏结构：

1. 当前目标与数据新鲜度；
2. 一句可解释结论；
3. 三个最高优先级差距；
4. 唯一下一步行动；
5. 下方再展示岗位摘要、证据覆盖和计划进度。

避免四个同权重 KPI 卡片开场。数字只有在能帮助决策时才占据大字号。

### 7.3 能力与证据

- 默认采用可排序的能力矩阵或分组列表，不以复杂节点图作为主视图；
- 列包含能力、目标等级、当前等级、置信度、差距、证据数和下一动作；
- 点击一项后在详情区展示等级锚点、证据、冲突和历史变化；
- 能力依赖图只作为辅助解释，节点数量受控且有列表替代。

### 7.4 岗位发现

- 顶部保留目标摘要、筛选和最后刷新时间；
- 桌面使用结果列表 + 详情面板，移动使用列表到详情；
- 详情顺序为：是否可投 → 为什么匹配 → 硬门槛 → 能力差距 → 来源与申请入口；
- 来源、开放状态和核验时间不得折叠到默认不可见区域。

### 7.5 测评与面试

- 使用 800px 聚焦阅读列，隐藏不相关导航干扰；
- 顶部显示阶段、题目进度、保存状态和退出后可恢复说明；
- 题目、回答区和提交动作保持稳定位置，避免每题布局跳变；
- 评分报告先展示能力变化和证据，再展示长篇模型总结；
- 面试追问说明“为什么问”，但不泄露评分答案。

### 7.6 学习计划

- 以本周任务和时间预算为主，不以自由拖拽看板为首版核心；
- 每项任务展示对应差距、预计时长、产物、验收标准和复测入口；
- 依赖未满足时说明原因和前置任务；
- 计划调整展示变化原因，不静默移动用户日程。

### 7.7 简历建议

- 桌面使用原文与建议的并排对照，移动使用标签切换；
- 每条建议绑定证据，并提供接受、编辑、忽略；
- 未确认内容不直接覆盖原文；
- 风险提示贴近具体建议，不使用全页泛化免责声明替代逐条校验。

## 8. 状态设计

每个数据页面至少实现：

| 状态 | 必须展示 |
|---|---|
| 初始空状态 | 为什么为空、开始动作、所需输入 |
| 加载 | 正在执行的真实阶段；已有内容保留 |
| 局部成功 | 已完成结果、未完成部分和影响 |
| 完整成功 | 结论、来源、新鲜度和下一动作 |
| 可重试失败 | 人类可读原因、重试范围、已保留内容 |
| 不可重试失败 | 原因、替代入口、联系或人工处理方式 |
| 无权限 | 不泄露资源是否存在，提供返回动作 |
| 过期 | 最后核验时间、过期影响、重新核验动作 |

骨架屏只用于结构稳定且短暂的加载；未知时长任务使用阶段进度。空状态不放无关插画或营销文案。

## 9. 数据可视化

- 比较能力差距：排序条形图、点图或表格；
- 展示能力变化：前后对照条、折线或事件时间线；
- 展示证据构成：分组列表优先，必要时使用堆叠条；
- 展示计划：周视图和任务列表；
- 展示匹配构成：分项条形图，不用单一环形分数；
- 展示单一覆盖率/完成度（如证据覆盖度）时可使用环形进度，但必须同时给出百分比数字、分子分母、分类标记和文本结论，环形不得作为唯一信息载体；环形只表达“已确认证据占比”这类可核算事实，不得用于表达匹配度或能力总分；
- 默认不使用雷达图、3D 图、速度表、装饰性节点网络和超过六种颜色的图例；
- 图表必须有文本摘要、单位、样本范围、更新时间和键盘/屏幕阅读器可访问的替代信息。

## 10. 文案规范

- 使用“能力估计”“证据不足”“待确认”“建议”，不使用“认证”“保证”“绝对适合”；
- 错误信息说明发生了什么、哪些内容受影响、用户能做什么；
- 不用“AI 已为你全面分析”等空泛措辞，说明具体处理阶段；
- 时间、等级、百分比和岗位状态使用统一格式；
- 中英文术语首次出现时提供中文解释，后续保持一致；
- 不用 Emoji 作为功能图标或状态图标。

## 11. 可访问性

- 正文和交互文本达到 WCAG AA 对比度；
- 所有交互可通过键盘完成，焦点顺序符合视觉顺序；
- 焦点环始终可见，不以移除 outline 作为美化；
- 图标按钮有可访问名称；表单错误与字段建立程序关联；
- 状态变化通过 `aria-live` 或等价方式通知，但避免重复播报；
- 颜色、位置和图形都不能成为唯一信息载体；
- 支持 200% 缩放，主要流程不重叠、不裁切；
- 尊重 `prefers-reduced-motion`。

## 12. 动效与性能

- 控件反馈 120～160ms，面板/抽屉 180～240ms；
- 动效只服务于层级、反馈、状态变化和空间关系；
- 禁止滚动劫持、长时间入场动画、粒子背景、循环装饰动画和为展示而固定滚动区；
- 加载中不对整个页面使用模糊或低透明度；
- 玻璃拟态按 §4.5 约束使用；首屏关键渲染路径不依赖 `backdrop-filter`，模糊元素不得晚于其承载的内容出现；
- 目标：LCP < 2.5s、INP < 200ms、CLS < 0.1；
- 图表和富文本按需加载，动画库不得成为首屏必需依赖。

## 13. 图标、插图与素材

- 图标家族统一为 **Lucide**（线性、24px 网格、`stroke-width` 1.8～2.1），禁止在同一产品混用多套图标；
- 图标默认 16/20/24px，线宽和视觉尺寸一致；
- 图标真实路径通过 `better-icons` 获取后内联或封装为组件，不凭记忆手写近似路径，保证与图标库保持一致；
- 不使用 Emoji、无来源的品牌 Logo 或自绘替代图形；
- 产品工作台不依赖大幅插图；空状态如需插图，必须简洁、可移除且不遮盖操作；
- 不使用虚构用户头像、假评价、假公司 Logo 或无法证明的指标。

## 14. 实现约束

- 技术栈沿用 Vue 3 + TypeScript；未经评审不新增整套 UI 框架；
- 先建立语义令牌和共享基础组件，再开发业务页面；
- 组件 API 围绕业务状态设计，不把后端原始枚举直接散落在模板中；
- 所有列表使用稳定 key，异步操作处理重复提交、取消、恢复和错误；
- 图标、日期、数字、状态文案通过统一适配层输出；
- 页面不得用 Mock 结果冒充真实集成；Mock 模式必须有清楚标识；
- 不修改既定路由、接口字段或业务文案来迁就视觉组件。

## 15. 云码道执行协议

任何创建、重构或评审前端页面的任务必须：

1. 阅读本文、任务对应模块手册和 `14-contracts-and-schemas.md`；
2. 检查已有组件、令牌和页面，不重复建立另一套视觉语言；
3. 开工前简述页面对象、用户主任务、设计方向、信息密度和关键状态；
4. 明确桌面与移动布局、正常/空/加载/局部失败/失败/过期状态；
5. 优先实现共享令牌、布局和组件，再实现页面特例；
6. 使用真实契约或明确标识的 Mock 数据检查长中文、空值、错误和极端数据；
7. 完成后提供视觉验收截图和检查结果，不以“代码已编译”代替界面验收。

本地已安装 `ui-ux-pro-max` 时，可用其搜索结果补充方案，但它不是事实来源。搜索得到的配色、框架和组件建议若与本文、技术冻结或现有代码冲突，以本项目文档为准。

## 16. 视觉验收矩阵

CP-010 页面至少检查以下视口：

- 1440×900：主要桌面工作台；
- 1024×768：收起导航和平板横屏；
- 390×844：主流移动视口；
- 200% 浏览器缩放：可读性和布局回流。

每个主要页面的验收清单：

- [ ] 页面首屏能说明当前状态和唯一下一步；
- [ ] 来源、置信度、开放状态和最后核验时间按需可见；
- [ ] 正常、空、加载、`PARTIAL`、失败、过期状态均有设计；
- [ ] 长中文、长企业名、多个地点和 `UNKNOWN` 不破坏布局；
- [ ] 桌面、平板、移动无意外横向溢出；
- [ ] 键盘可完成主要流程，焦点清楚；
- [ ] 文本和控件对比度达到 WCAG AA；
- [ ] 颜色不是状态的唯一表达；
- [ ] 主要点击区域不小于 44×44px；
- [ ] 减少动效设置生效；
- [ ] 渐变只出现在主按钮、选中导航项和数据图形，没有装饰性渐变背景或“AI 感”光带；
- [ ] 没有荧光光晕、高饱和彩色阴影、玻璃嵌套玻璃、Emoji 图标、假指标和无依据文案；
- [ ] 玻璃层上的文本按最不利底层色核算仍达 WCAG AA，且 `@supports` 降级路径可用；
- [ ] 没有为页面单独发明颜色、圆角、阴影或字号体系；
- [ ] 真实 API 联调时没有用静态结果覆盖失败状态；
- [ ] 截图与当前提交、测试结果和 CodeArts 工作项关联。

## 17. 变更管理

以下改动需要在 CodeArts 工作项中说明原因、影响页面和迁移方式：

- 新增或修改全局颜色、字号、间距和圆角令牌；
- 引入 UI、图表、图标或动画依赖；
- 修改一级导航、路由名称或核心页面结构；
- 改变等级、置信度、来源、开放状态或错误的表达方式；
- 修改移动端关键流程；
- 与本文明确规则不一致的视觉实验。

如果真实用户实验表明当前规则阻碍理解或操作，应以数据更新本文，而不是在单个页面长期保留例外。
流程要求：任何按本节执行的改动，除 CodeArts 工作项外，必须同步在 `18-current-state-and-next-actions.md` 记录**变更理由、影响页面与令牌迁移方式**。若 CodeArts 工作项尚未创建（如赛事前期以 GitHub 为唯一远端时），18 号文档即为临时留痕载体，待工作项建立后回填编号。
