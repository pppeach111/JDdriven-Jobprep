# 08 证据化简历工作台开发手册

## 1. 模块定位

简历模块用于将用户已有经历与经过验证的新成果，针对目标 JD 组织成清晰、真实、可追溯的简历版本。它不是复杂排版 SaaS，也不与魔方简历等成熟模板工具正面竞争。

核心差异：每一条修改建议都应回答：

- 它对应 JD 的哪项要求？
- 它来自用户的哪段经历或证据？
- 哪些数据已经验证，哪些需要用户确认？
- 修改后是否可能夸大或改变事实？

## 2. MVP 功能

- 导入 PDF/DOCX/文本简历；
- 解析教育、技能、项目、实习、奖项；
- 用户逐项确认结构化结果；
- 将简历陈述关联到标准技能和证据；
- 针对目标 JD 标出缺失、弱表达和无证据声称；
- 生成逐句修改建议；
- 显示原文/建议/修改理由/证据；
- 保存多个岗位靶向版本；
- 提供 1～2 套 ATS 友好模板；
- 导出 PDF 可放入 P1，但至少能复制结构化内容。

## 3. 简历解析

结构化字段：

- 个人联系信息；
- 教育经历；
- 技能；
- 项目经历；
- 实习/工作经历；
- 获奖与证书；
- 每条经历中的动作、技术、对象、指标和结果。

解析完成后必须让用户确认，尤其是：

- 时间范围；
- 个人职责；
- 性能指标；
- 团队成果与个人成果；
- 技术栈；
- 联系信息。

## 4. 证据化改写

### 4.1 建议类型

| 类型 | 示例 |
|---|---|
| 表达优化 | 删除空泛词，突出动作与结果 |
| 岗位对齐 | 将相关经历前置或补充真实技术细节 |
| 证据不足 | “熟练”缺少项目或测评证据 |
| 指标待确认 | 性能提升30%没有测量方法 |
| 事实冲突 | 时间、技术或结果与其他材料矛盾 |
| 内容缺失 | JD核心能力已有证据但简历未体现 |
| 内容弱相关 | 版面有限时建议删除低相关内容 |

### 4.2 严格禁止

- 凭空生成公司、项目、奖项或职责；
- 将团队成果全部写成个人成果；
- 自动制造精确数字；
- 将测试成绩直接写成工作经验；
- 将“了解”改写为“精通”；
- 未经确认直接覆盖用户原简历。

## 5. 修改工作流

```text
导入原简历
  → 结构化解析
  → 用户确认事实
  → 对齐目标 JD
  → 检查能力与证据覆盖
  → 生成逐条建议
  → 用户接受/编辑/拒绝
  → 事实一致性复查
  → 保存岗位版本
```

所有建议保留版本和用户决策，可用于评估建议接受率。

## 6. 与能力图谱联动

### 6.1 简历到图谱

简历陈述产生低到中等可信证据，用于发现需要测试的能力，不能直接证明高级水平。

### 6.2 图谱到简历

只有满足下列任一条件才建议新增能力成果：

- 有用户确认的真实项目证据；
- 有可复现的微型实践及输出；
- 有代码、测试、报告或公开作品链接；
- 有用户确认的课程/证书，且表述不夸大实际能力。

### 6.3 示例

原文：

> 使用 Redis 优化系统性能。

如果只有简历自述，建议应是：

> 请补充缓存对象、策略、测量指标和你的具体职责；当前证据不足以生成量化结果。

如果实践已经验证，可给候选表达：

> 为校园论坛热点帖子设计 Redis 缓存与失效策略；在本地 500 并发压测条件下，接口 P95 响应时间由 420ms 降至 135ms。

同时标注“本地压测条件”，避免将实验结果包装成线上生产数据。

## 7. ATS 友好模板

首版模板原则：

- 单栏为主；
- 标准章节标题；
- 文本可复制；
- 不使用重要信息图标化；
- 避免复杂表格、浮动文本框和进度条；
- 控制一页或两页但不强制压缩；
- PDF 导出后检查字体、换行和文本提取。

不投入自由拖拽、几十种主题、照片美化等低价值功能。

## 8. 评价指标

- 结构化字段准确率；
- 用户事实纠正率；
- 建议接受/编辑/拒绝比例；
- 建议的证据引用覆盖率；
- 无依据新增事实数量，目标必须为 0；
- 针对目标 JD 的关键能力覆盖变化；
- 人工评审的清晰度、真实性和岗位相关性；
- PDF 文本可解析率。

## 9. 验收标准

- 用户可看到并确认解析结果；
- 所有修改建议显示理由和证据；
- 缺少证据时系统请求补充而不是虚构；
- 多岗位版本互不覆盖；
- 能比较两个版本的内容差异；
- 已验证实践能够安全转化为简历候选；
- 任何自动内容在保存前由用户确认。
