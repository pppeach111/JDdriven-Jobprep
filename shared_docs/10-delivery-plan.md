# 10 十二周开发计划与四人分工

## 1. 时间范围

- 开始：2026-09-07
- 初赛目标提交：2026-11-30
- 完整开发周期：12 周
- 计划原则：11月23日起进入功能冻结，11月30日仅作提交缓冲。

> 注意：赛事页面可能要求“三名学生 + 一名指导教师”。当前四名学生必须尽快向赛事方确认资格。以下按四名开发成员分工，不代表四人都必然符合报名规则。

## 2. 建议角色

### 成员 A：产品、数据与评测负责人

- 需求边界、原型和用户流程；
- Java 能力标准库与题库组织；
- 数据标注规范、用户实验和评测报告；
- 答辩故事线和材料统筹；
- 同时承担部分前端或测试工作，不能只做文档。

### 成员 B：岗位发现与 AI 负责人

- 搜索查询生成、官方域名识别；
- 网页抓取、动态渲染和正文抽取；
- JD/岗位结构化提取；
- 大模型输出 Schema、提示词和质量评测；
- 资源链接核验。

### 成员 C：后端与图谱负责人

- Spring Boot 业务 API；
- 数据库模型；
- 硬门槛、能力估计、差距排序和计划规则；
- 测评状态机与证据写回；
- 权限、审计、隐私与接口测试。

### 成员 D：前端、云部署与集成负责人

- Vue 3 交互页面；
- 能力矩阵、测评、面试和课程表；
- 文件上传、结果引用和错误恢复；
- 华为云环境、流水线、监控和演示部署；
- 端到端集成测试。

所有核心模块至少有第二责任人，避免单点失联。

## 4. 每周节奏

### 周一

- 回顾上周数据和问题；
- 在 CodeArts 确认本周任务、负责人和验收；
- 冻结本周接口和数据契约。

### 周三

- 进行15分钟集成检查；
- 提前暴露接口、模型和部署问题；
- 不等到周末才合并。

### 周六

- 进行端到端演示；
- 用真实样例而非 Mock 数据验收；
- 记录失败案例和下周优先级。

### 周日

- 合并稳定分支；
- 更新指标、文档和演示环境；
- 冻结本周里程碑标签。

## 5. 关键依赖

```text
统一数据模型
  ├─→ JD/简历解析
  ├─→ 能力图谱
  └─→ 前端展示

能力图谱
  ├─→ 自适应测评
  ├─→ 靶向面试
  ├─→ 学习路径
  └─→ 简历建议

官方岗位发现
  └─→ 真实岗位推荐与最终演示
```

第3周结束前数据模型仍不稳定，会拖慢全部模块，必须优先解决。

## 6. P0 功能完成定义

一个功能只有同时满足以下条件才算完成：

- 有明确用户入口和成功/失败状态；
- 接口、数据和错误路径实现；
- 至少有自动测试或可复现验收脚本；
- 关键结果带来源和日志；
- 已部署到集成环境；
- 由非开发者本人完成一次验收；
- 更新相应文档和 CodeArts 任务状态。

## 7. 降级顺序

若进度滞后，按以下顺序删除或简化：

1. 取消语音、实时对话和复杂动画；
2. 取消自由拖拽课程表和 ICS 导出；
3. 简历只保留建议和单模板，不做复杂编辑器；
4. 企业从30家缩至15家高质量稳定站点；
5. 能力项从25项缩至15项核心技能；
6. 微型实践缩至3个高质量任务。

不能删除：证据图谱、自适应测评、官方岗位核验、差距到学习再到复测的闭环。

## 8. 风险触发线

- 第2周末仍无法稳定解析 JD：立即缩小格式范围，优先文本和 PDF；
- 第4周末官方岗位成功率低于50%：减少企业并建立配置化适配器；
- 第6周末自适应测试未跑通：暂停简历模板开发；
- 第8周末闭环仍未串联：停止所有非 P0 页面；
- 第10周末仍未云端部署：全员转向部署、数据和演示；
- 第11周不得新增大型功能。

- README、部署和复现文档；
- 数据集说明与脱敏样例；
- 评测报告与失败案例；
