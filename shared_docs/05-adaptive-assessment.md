# 05 自适应能力测评模块开发手册

## 1. 模块目标

通过短时、分层、多题型测试，对能力图谱中的关键技能进行低成本校准。模块输出的是“当前能力估计与置信度”，不是正式资格认证。

核心原则：

- 简历和目标 JD 决定优先测什么；
- 题目根据当前能力估计动态变化；
- 不用一类题型推断全部能力；
- 开放题按明确评分量表逐项评价；
- 高等级能力必须由场景或实践证据支撑；
- 复测使用等价新情境，不简单重复原题。

## 2. 能力维度

每项技术技能按需映射到以下维度：

| 维度 | 说明 | 合适题型 |
|---|---|---|
| 概念理解 | 知道术语、作用和基本原理 | 选择、判断、短答 |
| 代码阅读 | 能理解代码执行和风险 | 输出判断、找问题 |
| 实际应用 | 能根据需求选择和使用技术 | 场景方案题 |
| 故障诊断 | 能结合日志与现象定位问题 | 日志、代码、排错题 |
| 方案设计 | 能权衡性能、一致性、复杂度 | 开放设计题 |
| 技术表达 | 能清晰说明个人决策与贡献 | 文本面试 |
| 实践实现 | 能产出可运行、可验证结果 | 微型实践任务 |

综合等级必须展示各维度分布，避免“概念题高分=会工程实践”的误判。

## 3. 测评模式

### 3.1 快速摸底

- 时长：8～12分钟；
- 题量：8～15题；
- 目标：确定 L0～L3 的大致区间；
- 题型：客观题为主，至少一题代码阅读或场景题；
- 结束条件：能力区间稳定，或达到时间/题量上限。

### 3.2 岗位靶向测试

- 从目标岗位的关键能力、证据不足能力中选题；
- 优先测量会改变“是否建议投递”的技能；
- 不测已经有高可信实践证据且仍新鲜的能力；
- 输出岗位级能力覆盖和待验证项。

### 3.3 专项复测

- 在完成学习任务后触发；
- 只覆盖本次要验证的薄弱点及必要前置能力；
- 使用与训练材料不同的情境；
- 将“记住答案”和“能迁移解决问题”区分开。

### 3.4 微型实践

- 时长：30～90分钟；
- 输入：小型代码仓库、需求与测试；
- 输出：提交、测试结果、说明或性能数据；
- 作用：为 L3 以上能力提供强证据；
- 首版不做通用在线 IDE，可提供仓库模板和自动测试脚本。

## 4. 题库设计

### 4.1 每道题必须包含

```text
题目ID、版本、岗位族
主技能、次技能、能力维度
难度等级 L1～L5
题型、题干、选项/材料
标准答案或评分量表
常见错误和追问方向
预计用时
曝光次数与启停状态
创建人、审核人、更新时间
```

### 4.2 Java 后端首版题量

建议 20 项能力，每项：

- 3～4道客观题；
- 2道代码阅读/故障诊断；
- 1～2道场景题；
- 1个可选微型实践。

总计约 140～180 道题，足够支撑演示和小规模评估。题目质量比数量更重要。

### 4.3 分级锚点示例：Redis 缓存设计

| 等级 | 可观察表现 |
|---:|---|
| L1 | 知道缓存用途和常见数据结构 |
| L2 | 能为简单查询使用缓存并设置过期时间 |
| L3 | 能处理穿透、击穿、更新和基本一致性 |
| L4 | 能结合流量、一致性、降级和监控权衡方案 |
| L5 | 能设计复杂缓存体系并通过数据验证、指导优化 |

题目难度必须与这些行为锚点对应，而不是由出题者主观标“困难”。

## 5. 自适应选题策略

### 5.1 首版规则引擎

```text
1. 从简历和现有证据得到初始等级与置信度；
2. 选择最可能改变判断的能力和维度；
3. 从当前估计等级附近抽题；
4. 连续高质量答对则提高难度；
5. 连续答错则降低难度或换题型；
6. 同一结论至少需要两种不同证据；
7. 达到稳定阈值、题量上限或时间上限时结束。
```

示例：初始估计 Redis L2，先出 L2 代码阅读；答对后出 L3 场景题；若回答正确，再出 L4 故障追问；若失败，用另一道 L3 题确认边界，最终给出 L3 附近估计。

### 5.2 选题得分

```text
question_value =
  岗位能力重要性
  × 当前不确定性
  × 区分相邻等级能力
  × 未覆盖维度系数
  × 题目质量系数
  × 未曝光系数
```

不要只按难度线性出题，也不要完全随机。

### 5.3 后续增强

样本量足够后可引入项目反应理论或贝叶斯更新，但初赛不应为了算法名词牺牲可用性。没有足够作答数据时，不宣称已经训练出高可靠测量模型。

## 6. 评分设计

### 6.1 客观题

由确定性程序评分：

- 单选/多选；
- 判断；
- 代码输出；
- 排序；
- 单元测试结果；
- 明确数值或关键步骤。

### 6.2 开放题

每道题定义评分量表。例如缓存方案题 20 分：

| 评分项 | 分值 |
|---|---:|
| 正确选择缓存对象 | 3 |
| 合理的过期策略 | 3 |
| 数据一致性处理 | 4 |
| 穿透/击穿处理 | 4 |
| 故障降级 | 3 |
| 方案取舍解释 | 3 |

大模型必须输出：

- 每项得分；
- 引用的用户原句；
- 缺失点；
- 无法判断项；
- 总分与评分置信度。

若模型无法引用回答中的证据，不得给对应项高分。低置信或边界结果进入人工复核样本，不直接作为高权重证据。

## 7. 能力更新

每次作答产生一条 Evidence。一次测评结束后，能力图谱服务按照统一规则聚合，而不是由测评模块直接覆盖等级。

示例输出：

```json
{
  "skillId": "redis-cache-design",
  "dimensions": {
    "concept": 3.8,
    "codeReading": 3.1,
    "diagnosis": 2.2,
    "design": 1.8
  },
  "suggestedLevel": 2.7,
  "evidenceReliability": 0.72,
  "weakPoints": ["故障降级", "并发更新"],
  "recommendedNextEvidence": "MICRO_PRACTICE"
}
```

## 8. 复测与新鲜度

- 相同题目在短期内不重复展示；
- 复测使用相同能力点、不同上下文和参数；
- 学习后必须有迁移题，不能只考学习材料原句；
- 长期未使用不直接降低等级，只降低置信度；
- 关键能力距离最后验证超过 90～180 天时提示快速复测；
- 用户可查看历史等级变化及原因。

## 9. 反作弊边界

本产品是个人成长工具，不是正式考试，反作弊无需成为首版重点。仍应：

- 随机化等价题和选项；
- 记录异常短时作答；
- 开放题采用动态追问；
- 高等级必须有实践证据；
- 报告明确“结果用于自我评估，不代表资格认证”。

不要投入复杂人脸监考、锁屏或摄像头检测。

## 10. 验收标准

- 测试能根据作答动态升降难度；
- 同一能力至少包含两种题型；
- 每个开放题有明确评分量表；
- 每个 AI 评分均引用用户回答；
- 只有客观题时能力置信度受到上限限制；
- 复测题与训练内容不是原样重复；
- 10分钟内能稳定给出 2～4 项关键能力估计；
- 与专家/高年级学生人工评分的一致性达到预设指标。
